## 4. Business rules (keep consistent)

**Budget (ข้อบัญญัติ)** — hierarchy แผนงาน › งาน › งบ › หมวด › ประเภท › รายการ, items kept in document order.
- Each fiscal year has **its own ordinance** (`ordinances` table: title, agency, source, total). Importing a book
  creates the budget of *that* year only; its other columns (รายจ่ายจริง N-3/N-2, ประมาณการ N-1) go to
  `budget_actuals(kind)` for the multi-year comparison; a year whose own ordinance is loaded always uses it.
- Balance: `งบหลังโอน = ตามข้อบัญญัติ + โอน/เพิ่มเติม`; `คงเหลือ = งบหลังโอน − จองเงิน − ก่อหนี้ผูกพัน − เบิกจ่ายแล้ว`.
  จองเงิน = requests ขออนุมัติ/อนุมัติแล้ว; ก่อหนี้ผูกพัน = ordered/inspected minus paid.
- Transfers are pairs (โอนลด/โอนเพิ่ม, deleting one deletes both); reductions cannot exceed the available balance.
- Colour bands per item (`proc_stage`): the **least advanced** non-cancelled procurement — 1 grey `#E2E2E2`
  รอตรวจรับ, 2 light orange `#FDE3C8` ตรวจรับแล้ว, 3 light blue `#D3E8FB` เบิกจ่ายครบ; column «การจัดหา» counts each.

**Procurement** — kinds ซื้อ จ้าง เช่า แลกเปลี่ยน; numbers `ซ.001/2570`, `จ.`, `ช.`, `ลป.`.
- Flow: ขออนุมัติ › อนุมัติแล้ว › ก่อหนี้ผูกพัน (ใบสั่ง/สัญญา) › ตรวจรับแล้ว › เบิกจ่ายแล้ว (or ยกเลิก).
  Every step runs `check_budget` — never above the remaining balance. A request must use a budget item of
  **its own fiscal year** (from its request date).
- Defaults (Settings, owner to confirm): วิธีเฉพาะเจาะจง ≤ 500,000 (ม. 56 (2)(ข)), WHT 1 % of the pre-VAT amount
  when a payment ≥ 10,000, fines 0.2 %/day (ซื้อ/เช่า) and 0.1 %/day with a 100 บาท/day minimum (จ้าง).
- **Automatic registration** (owner's answers): ซื้อ/แลกเปลี่ยน from **ค่าครุภัณฑ์** → asset register, from
  **ค่าวัสดุ** → stock card, at **inspection** (or at payment if inspection was skipped); repairs/services
  (จ้าง, เช่า, ค่าบำรุง/ซ่อม/ปรับปรุง) are not registered. Asset/material type chosen from the budget type
  (`target_for`); no lines → one line from the title. `register_missing()` backfills older purchases on open.
- แลกเปลี่ยน disposes the asset given away (method «แลกเปลี่ยน») at inspection.

**Assets / materials** — numbers `{org}-{type}-{seq:04d}/{fy}` (seq restarts each fiscal year); depreciation
straight line, salvage 1 บาท, capitalisation threshold 10,000 บาท, first/last year by days ÷ 365, full years =
one year's share; fiscal year 1 ต.ค.–30 ก.ย. (พ.ศ.). Stock valued FIFO; issue cannot exceed the balance on that date.

**Ordinance PDF reader** (`ordinance_pdf.py`) — e-LAAS books: «รายงานประมาณการรายจ่าย» levels by indentation
(x ≈ 47/57/67/77/87/98 pt), numbers by column; «รายงานรายละเอียดประมาณการรายจ่าย» gives คำชี้แจง (header line ends
with «จำนวน N บาท»), matched to items by amount + consonant skeleton in order. pdfminer.six backend (bundled),
pdftotext fallback; legacy Thai glyph codes U+F700–F71A mapped back (`fix_thai`), lone tone marks re-attached.
Check: parsed total must equal «งบประมาณรายจ่ายทั้งสิ้น» printed in the book.

**Screens** — fonts chosen from what the PC has (TH Sarabun ≈ 16 pt, else Leelawadee/Tahoma ≈ 11.5 pt) × screen
height (never below base); forms with > 9 fields use two columns in a scroll area with buttons outside; every
page and big dialog is wrapped in `scrolled()`; windows go through `fit_to_screen`; screens under 1600×950 open
maximised. Year spin boxes: wide and bold. Use `px()`/`pt()` for any new fixed size.

## 5. How to work

- Tests: `cd venitsupply && QT_QPA_PLATFORM=offscreen python3 -m pytest -q -p no:cacheprovider tests`
- Run from source: `pip install -r venitsupply/requirements.txt && python3 venitsupply/main.py`
- Self-test (what CI runs on the bundle): `python3 venitsupply/main.py --selftest <folder>`
- Screenshots: `xvfb-run -a -s "-screen 0 1600x900x24"` with `QT_QPA_PLATFORM=xcb`; build `MainWindow(path)` on a
  file filled by `venitsupply.demo.fill(Store(path))`, call `w.go(index)` and save
  `qa.primaryScreen().grabWindow(0)`; patch `QMessageBox.question/information` for modal prompts; exit with
  `os._exit(0)`. Also test 1280×720 and 1366×768. Send the PNGs, wait for approval.
- Installer: a push to `claude/**` that changes `venitsupply/` (without `[skip ci]`) runs
  `.github/workflows/venitsupply-windows.yml` (tests → PyInstaller → `--selftest` → Inno Setup → artifact
  `venitsupply-setup-<version>`; also the artifact `venit-supply-skill`). Bump `venitsupply/__init__.py` and
  `installer/release-notes.md` first. Link for the owner:
  `https://github.com/venidnid-creator/wanicn1/actions/runs/<run>/artifacts/<id>`; schedule a check with
  `send_later` (≈ 5 min) instead of polling. Release only on order: tag `venitsupply-v<version>` or dispatch
  with `release: true`.
- New ordinance for any agency/year: in the program «งบประมาณ › นำเข้าข้อบัญญัติ», or
  `python3 -m venitsupply.ordinance_pdf book.pdf out.csv`. Downloading from a government site may need the host
  added to the session network (the environment tools).
- **Keep this skill current**: after any change run `python3 venitsupply/tools/build_skill.py` (also run by the
  Stop hook in `.claude/settings.json` and by CI). Hand-written sections (rules, history, rules of business,
  roadmap) must be edited by hand when they change — add a row to §2 for every owner request.
